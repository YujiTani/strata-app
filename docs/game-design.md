# ゲームデザイン（洞窟発掘 × 放置ゲーム）

> 「ゲームがどう動くか（メカニクス・パラメータ・ボリューム）」を定義する。
> 関連: 機能の範囲は `spec.md`、整合性の方針は `architecture.md`、テーブルは `data-model.md`。
> ⚠️ サーバー権威・検証の扱いは必ず `architecture.md` を併読すること。

---

## 採掘ループ（コアの体験）

ゲームは **2D 横スクロール・一方向（右→左）に進むだけ**。経路の自由度はなく、進捗は「進んだブロック数」で表せる。

```
発掘ボタン押下
  → サーバーが SEED を発行（クライアントとサーバーが同じ map・同じ乱数列を共有）
  → 放置中、クライアント上で以下がループ:
      キャラが前方のブロックに衝突
        → ツルハシ耐久 −1、ブロック耐久 −（ツルハシパワー）
        → ブロック耐久が 0 になったら採掘イベント:
            ① ドロップ有無の判定（SEED ベースの決定論抽選で"予測"）
            ② ドロップ内容の判定（同上）
            ③ クライアントは「出た！」を演出表示（あくまで予測）
        → 次のブロックへ進む

  → 精算（一定間隔 or 帰還時）:
      クライアント: 「Nブロック進んだ」と進捗だけ報告
      サーバー    : 時間・スタミナ・耐久・パワーから上限を検証（超過は拒否）
                    同じ SEED から自分で再計算してドロップを確定 → インベントリ反映
      （予測と確定は決定論なので、ほぼ常に一致）
```

- これは「時間経過で報酬がたまる」型ではなく、**シミュレーションが実際に走る**型。
- ドロップの**確定はサーバー**。クライアントの「出た！」は SEED から再現した予測演出。
- 詳細な権威・検証・SEED/PRNG の扱いは **`architecture.md` を必ず参照**。

## スタミナと「倒れ込み」処理

- キャラは行動でスタミナを消費する。
- **スタミナが 0 になっても、実行中のツルハシ処理は最後まで走らせる**（1スイング＝完結した処理単位として扱う。途中で止めて状態を中途半端にしない）。
- 実行中の処理が無くなった瞬間にスタミナ 0 なら、そこで**倒れ込み**。
- ポップアップで提示:
  - **街に帰る** → スタミナ回復が速い
  - **回復アイテムを使う** → その場で回復（在庫消費 ＋ スタミナ加算を 1 トランザクションで）
- 倒れたままでも時間で回復し、再開可能。

## キャラクターのパラメータ

| パラメータ | 役割 | 学びとの関係 |
|---|---|---|
| スタミナ（上限/現在値） | 行動の制限。0 で倒れ込み | 時刻ベースの回復計算（主軸の応用） |
| レベル / 経験値 | 育成の達成感 | 集計・更新のシンプルな題材 |
| インベントリ上限 | 拡張を買う動機（経済の蛇口） | 上限チェックと整合性 |

## アイテム（ツルハシ）のパラメータ

| パラメータ | 役割 |
|---|---|
| 耐久値 | ブロック衝突で減少。0 で使用不可 |
| ツルハシパワー（発掘力） | 1 衝突あたりブロック耐久を削る量。ドロップ効率に影響 |

> パラメータは「達成感重視で多め」の方針で採用。ただし増えるほど採掘精算ロジック（区間ごとの精算）が
> 複雑化する点は認識済み。Week 2 の放置 tick は当初想定より重いマイルストーンになる。

## 村と建物（MVP）

- 村は最初、建物を **3 つまで**しか建てられない（数値はデータで保持し拡張容易）。
- 建物は素材アイテムで建設 → さらに素材を使ってアップグレード。
- **MVP の建物は 2 種類（両方とも市場を回すのに同等に必要）**:
  1. **ツルハシ生産**: 発掘効率（ツルハシパワー/性能）を上げるツルハシを生産
  2. **スタミナ拡張**: 放置できる時間＝スタミナ上限を強化
- 建物が生む産物・要求する素材は市場に流せる。
- アップグレード要件はデータ駆動（`building_recipes` を追加予定 → data-model.md 改訂対象）。

## MVP のボリューム（最小・主軸検証に必要な分だけ）

| 要素 | MVP の量 | 根拠 |
|---|---|---|
| フィールド | 1 種類（単一テーブル・深度なし） | 市場の必然性は素材のズレで作れる |
| アイテム定義 | 5〜6 種（素材コモン2・レア2 ＋ 加工品1〜2） | 「掘れる素材」と「村が要求する素材」のズレで市場が立つ最小数 |
| 建物 | 2 種（ツルハシ生産・スタミナ拡張） | 両方必要にすることで両素材に需要が立つ |
| 村の建設上限 | 3 | 企画どおり |

- 素材の多様性は「深さ」ではなく**ドロップ確率差**（レアは出にくい）で作る。
- これ以上の量は「面白さ」のための拡張であり、**システム完成後に AI エージェントで後追い**（MVP 完成判定に含めない）。

## 将来拡張アイデア（MVP 外・データ駆動で後から足せる）

- フィールドのランダム性（発掘開始時にどのフィールドかランダム）
- 深度による出現素材の変化（`drop_tables.depth_band`）
- フィールド特産品（希少素材の固有ドロップ）
- 日替わり天候による出現変化
- 建物の種類追加（食料生産・素材加工・武器販売 など）
- 資産家ランキング（入手アイテム価値＋建物価値の合算で TOP10。集計の持ち方は設計論点）

## 将来拡張（性質が違う・データ追加では済まない）
- **モンスター戦闘**（`drop_tables.is_monster` は予約済み）。新規ゲームロジックで主軸とは別系統。**non-goal 固定**。
