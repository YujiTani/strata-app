# ADR-0006: DB接続ドライバとpooled/unpooledの使い分け

- ステータス: 決定
- 日付: 2026-07-17

## コンテキスト

主軸である `SELECT ... FOR UPDATE` は、同一の物理コネクション上でトランザクションを開始〜終了まで
保持できることが前提。Neonは複数の接続方式（HTTP版のサーバーレスドライバ、TCPのプール接続、
TCPの直結）を提供している。

## 決定

アプリ実行時は素のTCP標準ドライバ（`postgres`パッケージ、プール接続）を使う。
マイグレーション（Drizzle Kit）は直結（unpooled）の接続文字列を使う。
`@neondatabase/serverless`（HTTP版）は使わない。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| `@neondatabase/serverless`（HTTP） | HTTPはリクエスト単位で完結し、インタラクティブなトランザクション（`BEGIN`〜`FOR UPDATE`〜`COMMIT`を
1つのセッションで保持）を維持できない。主軸（行ロック）が成立しなくなるため不可 |
| マイグレーションもpooled接続で実行 | PgBouncer（プーラー）経由だと、マイグレーションツールが保持しようとする
セッション単位のロック（DDL中の排他制御）をプーラーが横取りし、セッションが失われることがある |

## 理由

Fly.io上の常駐サーバーなのでTCPのコネクションを保持できる（サーバーレス関数のようにリクエスト毎に
使い捨てる制約が無い）。アプリ実行はプール接続で同時実行数をさばきつつ、マイグレーションだけは
直結にして「工事中に誰にも席を横取りされない」状態を保証する。

## 結果・トレードオフ

- 得たもの: `FOR UPDATE`が実際に機能する接続方式
- 理解の転換点: 「なぜマイグレーションはunpooled直結か」を一度は腹落ちできず棚上げにし、
  初回`drizzle-kit migrate`成功直後に再演して自分の言葉で説明できるようになった
  （`docs/progress.md` 2026-07-17。比喩: 席=実コネクション、札=セッションに紐づくロック、
  工事屋=マイグレーションツール、案内係=PgBouncer。「守る相手は他の客ではなく工事屋自身」）
- 現在保留中の課題: `.env.development`の`DATABASE_URL`と`DATABASE_URL_UNPOOLED`が
  同一の値（両方`-pooler`付きホスト名）になっている点が未確認のまま残っている。要検証
