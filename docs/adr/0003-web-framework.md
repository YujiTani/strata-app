# ADR-0003: バックエンドWebフレームワーク

- ステータス: 決定
- 日付: 2026-07-13

## コンテキスト

サーバーとクライアント間でend-to-endの型安全性を確保したい。バリデーションには使い慣れたZod系の
書き味を使いたい。Bunネイティブに動くフレームワークであること。

## 決定

Elysia.js を採用する。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| Hono | RPC機能はあるが、end-to-end型安全のための設計・記述の手間がElysiaのEden Treatyより大きく、
学習期間（8週間）に見合わないと判断して見送った |
| Express / Fastify | Bunネイティブではなく、型安全なRPC的な仕組みも標準では持たない |

## 理由

Elysiaは Bun ネイティブで動作し、Eden Treaty により end-to-end 型安全（サーバーの型がそのまま
クライアントの型になる）を得られる。バリデーションはStandard Schema対応で、使い慣れたZodと近い書き味を活かせる。

## 結果・トレードオフ

- 得たもの: サーバー・クライアント間の型安全性、Zodライクな書き味
- 払ったコスト: Elysia固有の型（`HTTPHeaders`等）とTypeScriptの標準的な型との不一致に遭遇した実例あり
  （`docs/progress.md` 2026-07-16、CORSヘッダー実装時のtypecheckエラー）
- 覆すきっかけ: Elysiaのエコシステムが小さく、必要なプラグインが揃わない場面が増えた場合
