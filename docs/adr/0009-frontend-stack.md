# ADR-0009: フロントエンド構成（ビルド・ゲームエンジン）

- ステータス: 決定
- 日付: 2026-07-13

## コンテキスト

「洞窟発掘×放置ゲーム」というゲーム的な題材だが、ゲームはガワであり学習の本体はバックエンドにある
（`CLAUDE.md`）。フロントに時間をかけすぎない構成が要る。

## 決定

ビルドツールは Vite（無印）、クライアントは Phaser を採用する。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| Vite+（プラス） | まだalpha版であり、Bun/Biomeとの組み合わせで問題が起きた場合の切り分けが難しくなるため見送り |
| Unity | 物理演算等の機能が今回のスコープ（横スクロール一方向の採掘演出）に対して規模過剰。
学習の主軸から外れる時間を消費するため不採用 |

## 理由

Viteは無印の安定版を選び、余計な不確実性を持ち込まない。Phaserは2D特化で、
「衝突→採掘は演出、結果はサーバーAPIが正」（`docs/architecture.md`）という設計方針に対して
過不足のない機能量。将来Tauriでデスクトップ化する余地も残る。

## 結果・トレードオフ

- 得たもの: フロント実装コストを抑えつつ、ゲーム的な見た目のデモが作れる
- 払ったコスト: Unityほどの物理演出の作り込みはできない（今回はそもそも不要と判断）
