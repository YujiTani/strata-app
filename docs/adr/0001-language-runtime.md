# ADR-0001: 言語・ランタイム・パッケージマネージャ

- ステータス: 決定
- 日付: 2026-07-13

## コンテキスト

8週間・約120時間で「データ整合性を守るバックエンド設計」を主軸に学習する個人開発。
セットアップに時間を割きすぎず、主軸の学習時間を最大化したい。

## 決定

言語は TypeScript、ランタイム/パッケージマネージャは Bun を採用する。
バックエンド・クライアント（`apps/client`）共通で使う。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| Node.js + npm/pnpm | ランタイム・パッケージマネージャ・テストランナー等が別ツールに分かれ、セットアップコストが主軸の時間を食う |
| Deno | エコシステム（Elysia等の候補フレームワーク）との親和性が薄い |

## 理由

Bun は「ランタイム・パッケージマネージャ・バンドラ・テストランナー」がオールインワンで、
セットアップが最速。8週間という期間の制約下で、脇役（環境構築）に割く時間を削り主軸に回すため。

## 結果・トレードオフ

- 得たもの: セットアップの高速化、`.env`自動ロード等の組み込み機能
- 払ったコスト: BunはNode.jsよりエコシステムが若く、ライブラリ互換性の落とし穴に遭遇するリスクがある
  （実際に Vitest は Bun 上でも Node 実行になる摩擦があった。ADR-0008参照）
- 覆すきっかけ: 本番運用で Bun 固有のバグに繰り返し当たるようなら Node.js への切り戻しを検討
