# ADR-0008: テストツール

- ステータス: 決定
- 日付: 2026-07-13（Week3で本格導入予定、`docs/roadmap.md`）

## コンテキスト

フロントエンド（Vite/Phaser）とバックエンド（Elysia）で共通のテストツールを使いたい。
Week3では「並行攻撃の自動テスト化（壊れる→直るを再現可能にする）」が主軸そのものに関わる。

## 決定

Vitest をFE/BE共通で採用する。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| Bun標準の`bun:test` | フロントエンド（Vite）との統合実績・エコシステムがVitestに比べて薄く、
FE/BEでツールを分けるとかえって学習コストが増える |

## 理由

FE/BEでツールを分散させない。BunでもVitestはNode実行になる摩擦があるが、
「ツールを1つに揃えることで学習コストを避ける」というトレードオフを受け入れた。

## 結果・トレードオフ

- 得たもの: FE/BE共通のテスト記法・実行コマンド
- 払ったコスト: Bunのネイティブテストランナーではなく、Node実行を経由する分のオーバーヘッドがある
- 現在の状態: `apps/server/package.json`の`test`スクリプトは未設定のプレースホルダのまま。
  Week3の「並行攻撃の自動テスト化（Vitest + 実Postgres）」で実際に導入する
