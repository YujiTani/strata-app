# ADR-0007: Lint / Format

- ステータス: 決定
- 日付: 2026-07-13

## コンテキスト

コードの静的検査（Lint）と整形（Format）のツールを決める必要があった。

## 決定

Biome を採用する。

## 検討した選択肢

| 選択肢 | 採用しなかった理由 |
|---|---|
| ESLint + Prettier | 2ツールの設定・依存関係を別々に管理する必要があり、セットアップコストが主軸の時間を食う |

## 理由

Biomeは1ツールでLintとFormatを統合しており、設定ファイルも1つで済む。ADR-0001と同じ理由
（脇役のセットアップコストを削り主軸に時間を回す）。

## 結果・トレードオフ

- 得たもの: 単一ツールでの高速なLint/Format
- 払ったコスト: ESLintに比べてルールセット・プラグインのエコシステムが小さい。
  独自ルールが必要になった場面ではESLintより選択肢が狭い
- 実例: package.jsonへのスクリプト追記時、インデントのタブ/スペース混在でフォーマットチェックに
  引っかかった経験あり（`docs/progress.md` 2026-07-16）
