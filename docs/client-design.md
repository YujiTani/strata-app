> 関連: ゲーム挙動の元定義は `game-design.md`、サーバー権威・検証境界は `architecture.md`（必ず併読）。

## 位置づけと AI 線引き

- クライアントは**全て演出**。ドロップ・通貨・進捗の確定はサーバーが行う（`architecture.md` 第一原則）。
- 描画・演出の実装は AI 線引きの ✅ 側であり **AI エージェントに委譲**する。
  Yuzu の役割は各ステップの成果物レビューと採否判断（脇役「AI出力を検証する姿勢」の実践）。
- ただし後述の「パラメータの扱い」はサーバー検証（🔒）に直結するため、設計判断は Yuzu が握る。

## 技術構成

| 項目 | 内容 |
|---|---|
| ビルド | Vite（`apps/client`。Bun workspaces の一員） |
| 描画 | Phaser 3（`AUTO`、960×540、`Scale.FIT` + 中央寄せ） |
| dev 時のサーバー接続 | Vite の proxy で `/health` → `http://localhost:8080`。相対パスで fetch でき CORS を回避。本番の配信・接続先設計は Week 6-7 |
| アセット | 図形プレースホルダー（矩形＋シンプル図形をコードで描画）。後からアセット差し替え可能な構造にする |
| 型検査 | `apps/client/tsconfig.json`（DOM lib あり・Bun 型なし）で個別検査。ルート tsconfig は Bun 前提のため `apps/client` を exclude。**注意: `extends` は `exclude` も継承するので、クライアント側で `exclude` を上書きし直す必要がある**（Step 1 でハマった点） |
| 検査コマンド | ルートの `bun run typecheck` が「ルート → クライアント」の順に両方検査。lint は `biome check .` が全体をカバー |

## 画面仕様（確定分）

- **2D 横スクロール・一方向（右→左）**（`game-design.md` に準拠）。
- **入場演出**: 画面表示時、キャラクターが画面外の右から洞窟に入ってくる。
  数マス進んだ先に最初のブロックがあり、ぶつかったらスイングを開始する。
- **グリッド**: 進行は 1 マス単位。ブロック配置は**歩行区間あり**
  （数マス歩く → ブロックに当たる → 壊す → また歩く）。
  歩行速度が進捗に意味を持つようにするための判断（連続壁だと速度がほぼ飾りになる）。
- **スクロール**: 1 マス進むごとにカメラがステップ追従。
  キャラは画面幅の約 60% の位置にアンカーし、**左に行きすぎて画面外に出ない**よう調整する。
- **採掘（スイング）**: ブロックの前で停止し、**クールダウン制**でツルハシを自動で振る
  （初期ツルハシは 3 秒に 1 回）。1 スイングでツルハシパワー分ブロック耐久が減り、0 で破壊 → 前進。
  スイング中は歩行しない（`game-design.md` の「1スイング＝完結した処理単位」と整合）。
- **クールダウンの可視化**: キャラ頭上に小さなゲージを表示（待ち時間がバグに見えないように）。
- **成長スケール**: 歩行速度・スイングクールダウン・ツルハシパワーは成長とともに変化する想定。
- **HUD**: タイトル ＋ サーバー疎通表示（`/health` の結果。疎通不能は ❌ で明示的に見せる）。
  開発用に現在パラメータのデバッグ HUD も表示する。

## パラメータの扱い（⚠️ サーバー検証との関係・最重要）

歩行速度・スイングクールダウン・ツルハシパワー・ブロック耐久は「時間→進捗」の変換式そのものであり、
サーバーの上限検証（`architecture.md` 🔒「N秒から最大何ブロック進めるか」）の**入力変数**になる。

```
最大進行ブロック数 = f(経過秒数, 歩行速度, スイング間隔, ツルハシパワー, ブロック耐久, スタミナ)
```

- 現段階では **モック値としてシーン内の定数オブジェクト 1 箇所に集約**する（散らばらせない）。
- 将来はクライアント/サーバーで値がズレないよう **`packages/shared` またはデータ駆動
  （`item_defs` / プレイヤーステータス）に移す**。ハードコード禁止（`spec.md` のデータ駆動原則）。
- この変換式と検証の設計は 🔒 **Yuzu が握る**（Week 2〜3 の精算・検証設計で確定）。
- SEED / 決定論 PRNG は未設計のため、**現段階の map・ブロック配置はローカルの仮実装**。
  Week 6-7 で SEED ベース（`packages/shared` の PRNG）に置き換える。
